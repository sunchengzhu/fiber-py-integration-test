# QUERY-04～06 可选共享环境

本改动只为已确认的三个真实付款查询用例增加串行共享入口，固定 Fiber `76307312e8de518c9a32074e6d16867c04de4f86`。默认仍是独立模式，原用例行、TEST-MAP、资金/费用、历史、租户隔离及稳定采样判据保持不变。

## 环境和状态边界

- `LSP_QUERY_ENV_MODE=shared` 只作用于 `TestTenantPaymentQueries`。CKB 沿用类级隔离，一个 owner 持有两个 FNN、两个 SDK 租户和 A–T、B–T、T–P 三条通道，整组结束时收尾。
- 每条方法仍新建 A/B 两笔真实付款，保留各自独立的证据目录、付款状态和判断基线。只共享明确列出的资源句柄，不复制 unittest 内部状态、清理栈或上一条的付款结果。
- 复用前检查进程、租户、通道身份与上一条最终六端余额；前后重读此前付款历史及 Paid 发票。资金和历史继续累计，不清空数据库、不重置余额、nonce 或请求历史。
- 三条方法的业务期限仍受首次 owner 的原始绝对预算约束。每笔两段 TLC、实际费用、一次经济结算的原有观测依据，以及至少五秒、至少三个完整样本、最大两秒采样间隔均保留。
- 失败、证据初始化异常、状态污染或归档错误使环境失效；后续方法不能继续复用或自动重建。入口使用 `-x`，失效门禁本身也独立于该参数成立。

这不是通用共享基类：检查点直接依赖本组的六端资金与付款历史。其他用例的状态前提和累计资金方向需另外评估。

## 收尾和证据

owner 的回调延后到整组收尾，归档安排在资源处理之后：

1. 正常清理受原 row 截止时间及最多 60 秒限制。期限耗尽或回调异常会保留原始失败，再以每个回调最多 15 秒继续处理剩余资源；失败回调最多重试一次。
2. 已知 SDK/FNN 进程另有逐项停止尝试。一个失败不会阻断后续资源；CKB 仍按原有 PID/cwd/command 身份核验规则回收。
3. 最终归档使用独立、最多 60 秒的预算，不延长业务期限。即使收尾恢复成功，原始超时或异常仍向外抛出，不能转换成通过。
4. `shared_environment/cleanup-status.json` 记录归档状态、异常、剩余回调和失效标志。`archive_complete=true` 不能单独代替原生退出码及进程退出检查。
5. 证据目录或首条记录初始化失败时，在证据根另存 `setup-failure-*.json`。诊断或清理再次失败只附加异常信息，不覆盖原始初始化异常。

提前回滚后的类级收尾复用已缓存结果，不重复执行 owner 回调或归档。失败路径保留原始数据、部分归档及异常信息，并恢复 `TMP_PATH`；归档失败明确报错。

方法级数据库副本来自运行中的节点，只作诊断，不作为可恢复的一致 RocksDB 快照。正常结束后的最终 owner 归档取自停止后的 FNN/SDK；链状态另有停止后备份。

共用 `HostedTenantFixture` 原样提取逐方法证据/预算初始化，另修复 PID 在 `kill(pid, 0)` 与 `ps` 之间退出的探测竞态：空 `ps` 输出后再次探测，权限不足或仍存活仍按活进程处理。原 zombie、字符串 PID 和身份核验规则未改变，PAYMENT-05 出站业务 helper 未改。

## 运行方式

使用项目已有 Python 环境、已验证的同源 bundle，并给每次执行分配新的绝对证据路径：

```bash
LSP_TEST_REVISION=76307312e8de518c9a32074e6d16867c04de4f86 \
LSP_TEST_BUNDLE="$PWD/download/fiber/pr-1623-7630731" \
LSP_QUERY_ENV_MODE=shared \
LSP_QUERY_KEEP_RUNTIME=1 \
LSP_PAYMENT_REPORT_DIR=/absolute/fresh-run/business \
CKB_CLI_HOME=/absolute/fresh-run/ckb-cli \
python -m pytest -o addopts= -p no:cacheprovider -x -vv -s \
  test_cases/fiber/devnet/lsp/test_tenant_payment_queries.py::TestTenantPaymentQueries
```

本次入口同时启用 `LSP_QUERY_KEEP_RUNTIME=1`，保留原始运行目录供核对。三条需在同一个 pytest 进程执行才会共享环境；逐条启动新进程不会复用。独立对照使用 `independent`，三条各起独立进程和环境。
