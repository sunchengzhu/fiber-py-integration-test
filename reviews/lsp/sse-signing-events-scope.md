# Gate1：SSE 签名通知的租户隔离与连接恢复

> 历史范围：对应 4028884 的旧事件传输。当前迁移见 [签名订阅 Gate1](signing-subscriptions-scope.md)及 [Gate2 用例](signing-subscriptions.md)；历史通过不代表当前版本通过。

**这批要验证：钱包能及时收到自己的待签请求；断线回来不会漏掉未完成工作；切换客户端后，新旧连接不会互相抢占，也不影响其他租户。**

沿用本对话的阶段：Gate1 确认范围、预期方向和环境能力；Gate2 展开带稳定 ID 的中文用例表及步骤；Gate3 在用例表明确通过后实现 Python 自动化。本轮不分配用例 ID、不新增 TEST-MAP，不编写或运行新增测试。

- 产品与实际 FNN、SDK agent、测试驱动：`40288844157cac8dd7fb025304be276cb1ac1f0b`。SSE 功能主要由 `8419c005` 引入。
- 测试仓库基于 `v0.10.0 / 6088115`，当前分支 `codex/lsp-core-regressions`。已有 16 条在上述产品版本通过，见 [运行说明](../../test_cases/fiber/devnet/lsp/README.md)。
- 已有用例通过真实 SSE 驱动开通、收款和关闭，覆盖部分断线、重启后的业务恢复；但没有直接断言事件内容的租户归属、会话 ID 的重连规则、接管后的 409 和旧 SDK 停止重连。
- 既有 `LSP-SIGN-02/03` 验证的是签名 RPC 的跨租户读取/提交，不替代新增 SSE 入口的隔离验证。已有重试用例也不能替代逐条核对 SSE 补发内容。

本轮围绕通道签名事件，复用私有 CKB 通道及真实 SDK。watchtower 事件的权限过滤、待签内容和最终结算另批验证。

## 先说清楚接口行为

SSE 是服务端保持连接、持续发送通知的 HTTP 接口：`GET /lsp/events`。租户身份来自 `Authorization: Bearer <租户 token>`。

| 概念 | 本批采用的含义 |
| --- | --- |
| 初始快照 | 连接建立时发送当前未完成的签名请求，再发送 `lsp.snapshot_complete`；它表示初始扫描结束，不表示通道已开通或所有请求已签完 |
| 后续通知 | 同一连接收到新产生的 `lsp.channel.signature_required`，内容包括对应通道及签名状态；JSON 的 `version` 为 1，事件名与 `type` 对应 |
| 断线补发 | 重新扫描当前待签状态；同一个尚未提交的请求允许在新连接再次出现，不要求通知跨连接只投递一次 |
| 当前会话 | 服务端通过 `X-Lsp-Session-Id` 返回连接所属会话；正常自动重连携带这个 ID |
| 主动接管 | 同租户建立不携带会话 ID 的新连接，会获得新会话并关闭旧连接；旧会话随后重连返回 409，真实 SDK 应停止自动重试 |
| 权限边界 | 会话 ID 不能代替 token；接管仅控制通知连接，不会撤销旧客户端 token 或禁止它提交仍然有效的签名 |

身份不能由查询参数指定；当前接口拒绝所有查询参数。operator token 也不能作为租户订阅。会话状态仅存在于当前 RPC listener 的内存中，不是跨重启的设备撤销记录。

## 本批范围：五个方向

以下为 Gate1 的范围与预期方向，Gate2 再将独立可观察行为拆成具体用例；不按参数个数机械增加用例数量。

| 方向 | 需要构造的条件 | 必须能判断的结果 |
| --- | --- | --- |
| 连接前后都能收到待签工作 | 分别覆盖连接前已有请求，以及初始快照完成后产生下一轮请求 | 已有请求出现在完整初始快照中；后续请求在原连接送达，内容与目标通道的持久化待签状态一致；通知本身不推进签名；真实 SDK 最后能完成原通道 |
| 通知不串租户 | A、B 都有真实待签请求，并分别建立连接；再尝试用 A 身份在 URL 中指定 B | 两个快照及后续事件只含各自通道的请求；带查询参数的请求被拒绝；错误订阅不改变任何待签状态，两个租户均可继续正常处理 |
| 无效订阅不破坏合法连接 | 已有合法连接时，分别发起缺少 token、无效 token、operator token 或格式错误的会话 ID 请求 | 请求被拒绝且不泄露待签内容；原连接仍能收到随后产生的新请求，不能只以原连接还能读到缓存帧就认定未受影响 |
| 断线后恢复当前请求 | 原连接已收到但尚未提交真实请求时切断传输；以原身份和原会话恢复；另观察上一请求已完成、下一请求待签时的重连 | 未提交请求的 ID 和业务内容保持一致；恢复后的初始快照反映当前待签工作，不把已完成请求当作当前任务；业务最终继续完成，不重复应用签名 |
| 接管后新旧客户端正确交接 | 同一租户的新连接主动接管已有连接，另一租户保持连接；旧连接按原会话重连 | 新连接取得当前待签工作；旧连接关闭、旧会话重连为 409；真实 SDK 的旧事件读取器结束而非去掉会话 ID 抢回连接；新连接及另一租户仍能接收后续工作 |

“初始快照”和“后续推送”、服务端接管和 SDK 停止重连，可以在 Gate2 分成独立行为，不要求硬凑为五条测试。
正常通知及隔离优先，连接异常随后；每个行为都使用独立环境，不依赖上一条留下的会话。

## 观察方式与避免假通过

1. **建立可比对的真实请求。** 利用已有签名 gate 暂停提交，在状态稳定时保存所属租户、channel ID、request ID 和完整签名业务内容；不能只验证事件名或收到任意 JSON。初始快照应冻结预期待签集合，完整解析到 `lsp.snapshot_complete` 后，再比对标记前收到的通道事件集合；SDK 最终完成开通不能替代快照完整性断言。
2. **明确每次订阅是否会接管。** 每个租户的观察者和 SDK 共用单连接规则。优先在现有 Python 转发器中观察真实字节；专门创建新订阅时，必须明确它是主动接管还是携带当前会话的重连。不能无意挤掉 SDK 后把影响当成产品故障。
3. **证明旧连接真的结束。** 控制具体连接的 EOF/关闭并记录握手头、状态码和单调时钟；修改 `pause_queries` 只影响后续请求，不能证明已经存在的 SSE 流断开。
4. **用正向事件证明连接仍可用。** 判断“不影响 B”或“非法请求没有挤掉 A”时，在目标连接上推进真实签名产生下一轮请求，并确认送达；仅观察一段时间没报错或收到心跳不够。
5. **分清接管前后。** 接管前已经传到客户端缓冲区的旧帧不能算接管后泄露；先确认新会话成功，再产生后续请求，检查旧会话不能重新获得订阅权。不能声称能从客户端内存追回已交付事件。
6. **不让客户端反复抢回。** HTTP 409 是旧连接后续重连的响应，不是旧的 HTTP 200 流能中途变成 409。接管前须确认旧 SDK 已完成当前事件处理、回到读取状态，或已及时收到暂停响应并通过 `--ack-held-events` 确认处理；SDK 等待事件处理完成时不会继续读取 EOF 或发起重连。然后确认旧流结束、携带旧会话 ID 的重连被拒绝，并独立观察真实 SDK 读取器结束原因及不再发起订阅，不能从服务端关流直接推断 SDK 已停止。
7. **保持签名真实性。** Python 负责订阅、传输故障、状态和结果断言，签名仍由当前真实 SDK 生成。纯 HTTP 观察客户端可以证明服务端行为，不能冒充“SDK 自动恢复/停止”的证据；不运行两个同时写同一 SDK 存储的签名进程。
8. **业务结果不能只看通知。** 本批优先用开通流程提供稳定签名轮次，收尾核对双方原 channel ID 就绪、原注资交易及 outpoint 一致、待签清空。通道建立成功不证明事件历史完整，也不证明 watchtower 已结算。

## 时间控制

| 时间依据 | 本批使用方式 |
| --- | --- |
| FNN 心跳 25 秒、单连接最长 300 秒 | 首批主动控制断线与接管，不靠等待五分钟到期触发恢复；不缩短产品常量。五分钟自然轮换及 token 在连接中到期留为后续边界 |
| SDK 连接超时 10 秒、读取超时 60 秒 | 正常断线注入应明确关闭传输，避免把挂住的连接当成已断线；具体超时错误单独记录 |
| SDK 重连退避从 500 毫秒增长，最大 30 秒，带随机抖动 | 不要求恰好在某一毫秒重连。Gate2 为握手、事件送达和停止重试分别制定有界等待；真实 409 后必须有读取器结束证据，不能仅在短于最大退避的窗口内数不到请求就判停止 |
| 业务安全窗口 | 沿用已评审的开通余量检查，先完成钱包注资提交，再截获通道签名。事件等待不能跨越适用开通期限后还期待正常恢复；若使用付款补充观察，则先核对实际 TLC 及授权有效期 |

具体等待上限会在 Gate2 与检查点一起列出。本轮不把测试等待预算写成产品响应时限，不修改宿主机时钟，不进行连接数量压力测试。

## 环境已有能力与剩余准备工作

| 项目 | 当前能力与 Gate2 需落实内容 |
| --- | --- |
| 节点、两租户、私有 CKB 通道、真实签名和最终状态核对 | 已有且在 `4028884` 上回归通过；复用 LSP 夹具 |
| SSE 转发与会话头 | `_signer_gate.py:forward_events` 已转发 Authorization、session ID 及响应头；目前没有逐帧记录或精确切断指定现有连接的接口，需在 LSP 局部补充有界观察/控制 |
| SDK 停止的证据 | 本地驱动调用官方 `subscribe_events`；读取器结束时驱动的 `events.next()` 返回空并退出。Gate2 核对退出原因及订阅次数，排除崩溃、被测试主动杀死等其他退出原因 |
| 签名暂停与 SSE 连通 | 已有 `--ack-held-events` 选项只把特定测试暂停视为事件已处理，保留连接；其他真实处理错误仍走重连。需要按场景明确选项，不能让人为暂停自动触发额外重连，破坏“原连接”断言 |
| 权限材料 | 已有两个真实租户 token、公开测试 operator token，足够验证本批身份隔离及基本拒绝；最小只读权限、过期 token、错误 node 绑定的完整矩阵不混入本批 |
| 新客户端接管 | 可用只读 HTTP 客户端接管原 SDK 的流，证明旧 SDK 停止；随后由单个 SDK 使用原存储恢复完成业务。接管者不是第二个签名进程，不能据此宣称验证双设备密钥同步 |

现有环境具备基础条件，但本批控制和观察接口尚未实现或试跑。Gate2 明确最小局部改动后再评审；不预设需要修改 Rust 驱动或公共框架，更不修改 FNN/SDK 产品源码。

## 本批不覆盖及后续入口

- watchtower 事件内容、其权限过滤和链上结算：转入已有 watchtower 专项。
- 凭证刷新后使用不同 token 共享同租户会话、连接中 token 到期：转入凭证生命周期专项。
- 300 秒自然轮换、慢消费者、16,384 连接上限、429/Retry-After、积压极限和浏览器代理行为：保留为后续传输边界，不把本批功能测试扩为压力测试。
- FNN 重启后会话重新建立、租户冷查询不唤醒、跨 listener 会话行为：已有业务重启仅为间接覆盖，本批不新增这些专项断言。
- 精确命中“订阅与首次快照同时发生状态变化”的并发窗口：普通先后顺序测试不能证明该竞态；保留源码/上游测试依据，不伪称 Python 已覆盖。
- 通知不是历史日志，没有事件 ID 或 Last-Event-ID 历史重放契约；不要求跨重连绝不重复、不把接管写成旧签名提交权限被撤销。
